# validation/ — 전향적 검증 (Prospective Validation)

> 목적: `analysis/`가 찾은 시그널이 **미래에도** 통하는지 검증한다.
> 사용자의 "**1개월 모니터링 후 검증**"이 바로 이 디렉토리의 핵심 — out-of-sample 검증.

## 왜 중요한가
과거 데이터에 맞춘 시그널은 거의 항상 과거엔 잘 맞는다(과적합). 진짜 가치는
**보지 못한 미래**에서의 성능뿐이다. 그래서 검증을 분석과 **분리된 디렉토리**로 둔다.

## 검증 방식
1. **전향적(prospective)**: 시그널 확정 후, 그 시점부터 신규 종목을 실시간 추적(약 1개월). 사전 등록된 예측만 채점.
2. **홀드아웃(holdout)**: 과거 데이터를 시간 분할(train/test), test 구간은 분석에 절대 미사용.
3. **워크포워드(walk-forward)**: 시간 이동 창으로 반복 검증.

## 채점 지표
- 정밀도/재현율, **우도비 유지 여부**(train 대비 test에서 LR 붕괴 점검)
- 거짓양성률(대조군에서 시그널 발생률) — 실전 비용의 핵심
- 리드타임 분포(시그널 → t0 까지 평균 며칠 전 잡히나)

## 절대 규칙
- 검증 구간 데이터를 **분석/튜닝에 역류시키지 않는다**(누출 = 검증 무효).
- 예측은 **사전 등록**(timestamp 동결) 후에만 채점. 사후 채점 금지.
- 결과는 성공/실패 모두 기록. 실패 시그널 폐기 로그 유지.

## 권장 파일
```
validation/
  pre_registration.md        # 사전등록(결정규칙·홀드아웃·전향적 계획) — 동결
  prospective_candidates.md  # 전향적 모니터링 코호트 v1 (2026-07-02 추출, 15건+제외4)
  prospective_log.md         # 사전 등록 예측 + 실제 결과(날짜 동결)
  holdout_report.md          # train/test 성능 비교
```
검증 통과 시그널만 `outputs/`로 승격. **검증 후 자동화 단계 진입.**

## 전향적 코호트 규칙 (v1 운영 중)
- 점수는 **보정 전 유사도** — "작전 확률" 해석 금지. 종목 단정 금지(모니터링 후보).
- 관찰 시작일 이후 정보로 점수 소급 수정 금지(as-of 동결). 재채점은 새 버전으로.
- 코호트 적중률(붕괴/제재 도달 비율)이 루브릭의 첫 캘리브레이션 데이터.
- **스코프: 주식만**(kr_stock+global_stock). crypto 제외(2026-07-02 결정, 루트 CLAUDE.md §6).

## 붕괴 타이밍 예측 + 매일 F/U 학습 루프
- 예측: `collapse_predictions.md` — 후보별 붕괴/디스트리뷰션 예상 창 + 구조 트리거 + 반증조건.
- 매집/셋업(급등 전): `preramp_watchlist.md` — 과거 전조와 유사한 셋업 관찰 리스트(회피 교육용, 매수신호 아님). 가장 순수한 out-of-sample 검증 자료 → 발화 여부 F/U로 리드타임·우도비 실측.
- F/U: `daily_followup.md` — 매일(거래일) 예측 대비 실제 대조. **적중=어떤 근거로 맞았나 / 오류=왜 틀렸나** 기록 → 학습자료 축적.
- ⚠️ 예측은 **가설적 시나리오**이며 확정 예언·매매 신호 아님. 반증조건 충족 시 즉시 오류 기록(사후합리화 금지).
